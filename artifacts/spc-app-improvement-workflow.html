Product Process

Improve the SPC app one verified work card at a time.

Your app is already useful. The next problem is control: bugs, parser limits, chart issues, and workflow ideas need a structure so they do not disappear into a long chat thread.

Operating Rule

One issue becomes one card. One card becomes one focused fix. One fix gets one test report.

Do not treat the chat as the source of truth. Use the chat to discuss, but capture the actual work as a small card with expected behavior and pass condition.

1Find
Bug or limitation appears during real use.
2Capture
Write one work card.
3Rank
P0, P1, P2, or P3.
4Diagnose
Read files and reproduce before editing.
5Build
Fix the narrow behavior.
6Test
Run unit, UI, and visual checks.
7Decide
Commit or revise.

Improvement Lanes

Chart Correctness Wrong spec lines, blank traces, unreadable labels, bad multi-dimension rendering. This is the highest-trust lane.
Parser Robustness Vendor headers, metadata detection, typos, shifted columns, file format variation.
Workflow Speed Batch export, saved presets, fewer clicks, reusable dimension sets, report-ready naming.
Visual QA Golden screenshots, live chart checks, not-blank validation, label/spec-line verification.
Reliability Local server, reboot behavior, dependencies, startup scripts, app health checks.
Code Structure Refactors that make chart, parser, UI, export, and state logic easier to change safely.

Priority

Priority Meaning Example Handling
P0 App cannot be used. App will not start, file cannot load. Stop current work and fix first.
P1 Output can be wrong or misleading. Spec line wrong, chart blank, grouping wrong. Fix before trusting the app for real reports.
P2 Workflow is slower than needed. Too many clicks, repetitive chart exports. Batch into focused workflow upgrades.
P3 Cosmetic or nice-to-have. Button position, copy polish, minor layout tweak. Do only when nearby or after higher priorities.

Recommended Roadmap

Phase 1: Trust the Chart
  • Different USL/LSL values across dimensions render clearly.
  • Single-point dimensions are visible.
  • Box Plot and Histogram handle multi-dim specs.
  • Labels stay readable with multiple selected dimensions.
Phase 2: Trust the Parser
  • Header detection handles common vendor variation.
  • Metadata/factor columns are detected reliably.
  • Vendor typos are surfaced as suggestions.
  • Detection results are visible to the user.
Phase 3: Reduce Repetition
  • Batch export remains stable.
  • Last-used controls can be reused safely.
  • Common dimension sets can become presets.
  • Export names are predictable.
Phase 4: Make Testing Routine
  • SPC test agent runs after changes.
  • HTML reports summarize test evidence.
  • Golden screenshots cover key chart states.
  • Failures explain what visually changed.

Test Evidence Required

Issue Type Required Evidence
Chart correctnessUnit test plus live chart screenshot or golden snapshot.
Parser robustnessReal-file parsing check or fixture test.
Batch exportZIP generation test plus one exported PNG check.
UI workflowLive UI smoke test with the exact controls used.
Server/reliabilityProcess/port check plus HTTP response.
Code refactorExisting tests pass and no user-facing behavior changes.
For chart changes, unit tests alone are not enough. The chart must be visually checked because the bug may be in rendering, labels, scale, or trace visibility.

Agent Flow

  1. Lead agent restates the work card and assigns lane/priority.
  2. Diagnosis agent inspects files, data, and code before any edit.
  3. Implementation agent fixes only that card.
  4. Test agent runs unit, UI, and visual checks.
  5. Lead agent writes a short result report with evidence and remaining risk.
The user should review the work card and visual evidence, not a giant transcript.

What To Do Next

  1. List the bugs and improvements you already found as titles only.
  2. Mark each one P0/P1/P2/P3.
  3. Pick one P1 chart/parser issue first.
  4. Create a full work card for that one issue.
  5. Let the agent team diagnose, implement, and test only that card.
